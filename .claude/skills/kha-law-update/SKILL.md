# KHA 법령개정 안내

## 목적

개정안을 조문순으로 줄이는 작업이 아니다. 회원사가 먼저 알아야 할 주택 관련 변화를 **빠짐없이 추출**한 뒤, **중요도와 정책주제에 따라 재구성**한다. 산출물은 평가·의견이 없는 객관적 `개정안 주요내용`이며 Markdown을 정본으로 한다.

## 작업 시작 전 필수 확인

1. 다음 두 원문을 요청한다. 둘 중 하나라도 없으면 **초안 작성을 중단**하고 누락 자료를 요청한다.
   - 개정문(개정법률안 / 개정령안 본문)
   - 신·구조문대비표
2. 사용자가 이미 제공한 원문은 **다시 검색하지 않는다.**
3. 입법예고문·개정이유서·부칙·보도자료가 별도 파일이면 필요한 범위만 추가 요청한다.
4. 부칙이 없어 시행일·적용례를 확정할 수 없으면 **임의 추정하지 말고** 자료 제공 또는 검색 허용을 요청한다.
5. 이번 산출물의 **대상 법령 범위를 먼저 확정**한다. 참고로 받은 다른 자료(샘플, 상위법, 관련 법률안)의 내용을 산출물에 섞지 않는다.

## 참조 문서

작업 중 다음을 읽는다.

- 작성·선별 기준: `references/writing-manual.md`
- 산출물 뼈대: `references/output-template.md`
- 최종 점검: `references/quality-checklist.md`

샘플과 비교하거나 스킬 일관성을 검증할 때만 읽는다.

- 확정 샘플: `references/samples/`
- 샘플의 편집원리·확인된 오류: `references/sample-notes.md`
- 회귀검증: `references/benchmark-protocol.md`

## 표준 작업 흐름

### 1. 자료 상태를 판정한다

- 각 파일이 개정문·대비표·부칙·이유서 중 무엇인지 식별한다.
- 변환된 Markdown이 있으면 원본 HWPX/PDF를 다시 변환하지 않는다.
- 표·조문번호가 깨진 변환본이면 더 나은 변환본을 요청한다.
- 여러 법령이면 법령별 입력 목록과 누락 여부를 먼저 정리한다.

### 2. 후보 조문 전수표를 만든다 (내부용)

| 조문 | 개정유형 | 주택 관련성 | 핵심 변화 | 시행·적용 | 근거 | 초안 반영 |
| --- | --- | --- | --- | --- | --- | --- |
| 법 §조항 | 신설/개정/삭제/이동 | 직접/간접/무관 | 대상·요건·수치·권리 변화 | 확인값 | 법률안/부칙/하위법령안/정부자료/확인필요 | 반영/보류/제외 |

- **개정이유·주요내용만 읽지 않는다.** 개정문 본문 → 부칙 → 신·구조문대비표를 **전수** 훑는다. 적용기한 정비나 항(項) 단위 신설은 이유서 목차에 없는 경우가 많다.
- 주택공급·건설·거래·취득·보유·임대·정비사업·토지·주택금융을 넓게 본다.
- 사업자에게 직접 적용되지 않아도 주택 거래·수요에 영향을 주면 후보에 포함한다.
- 순수 오탈자·표현정비만 제외한다. 인용조문 변경·항번호 이동도 실질효과가 있거나 불명확하면 남긴다.
- 감면·특례의 **추징, 재취득 제한, 계속 거주·보유, 신청기한, 단기보유 비교과세, 한도 안분** 등 결과를 뒤집는 조건은 반드시 기록한다.

### 3. 두 원문을 교차 검증한다

- 개정문에서 법적 변경 문언을, 대비표에서 현행 대비 효과를 확인한다.
- **개정유형은 개정문의 처분문구로 조문 단위마다 판정한다.** 판정표는 `writing-manual.md` 4.1 참조.
- 대상·요건·금액·비율·기간·절차·권리의무·특례의 신설·폐지를 대조한다.
- **법률안 밖의 수치·조건은 출처를 구분**하고, 근거자료가 없으면 본문에 쓰지 않는다.
- 두 문서가 충돌하면 임의 선택하지 않는다. `원문 확인 필요`로 표시하고 알린다.
- 현행법 문맥·위임관계·조문 이동 확인이 필요할 때만 `korean-law-mcp`를 쓴다. 검색 결과가 제공 원문을 대체하지 않는다.

### 4. 넓은 1차 초안을 작성한다

- **기본은 법령별 구성.** 법령 안에서는 조문순이 아니라 중요도·정책주제 순으로 묶는다.
- 여러 조문이 하나의 정책효과를 만들면 한 항목으로 통합하고 조문을 모두 병기한다.
- `정책주제별 통합모드`는 기본값이 아니다. 전환 조건은 `writing-manual.md` 6.4 참조. **사용자 승인 후** 적용한다.
- 1차 초안은 관련성을 넓게 잡는다. 사용자가 뺄 항목을 고를 수 있어야 한다.
- 협회 영향·평가·찬반·대응계획·전문가·언론 반응은 넣지 않는다.

### 5. 사용자와 2차 편집한다

- 초안과 함께 이것만 짧게 확인한다: 제외할 항목, 추가할 항목, 강조 순서, 통합모드 필요 여부.
- 선택을 반영해 중복을 합치고 제목·표·주석을 압축한다.
- **직접 관련 신설조문은 명시적 제외 지시 없이 삭제하지 않는다.**
- 한 법령당 통상 A4 1쪽, 필요시 2쪽. 다만 내용 누락을 위해 억지로 줄이지 않는다.

### 6. 시행일과 적용례를 정리한다

- 법령별로 시행일이 같으면 **해당 법령 끝에 `※ 시행일` 한 줄**로 쓴다. 적용례가 일부 항목에만 걸리면 괄호로 붙인다.
- 항목별 날짜가 여러 개면 법령 끝에 3열 표로 정리한다.
- `적용례`는 부칙에 규정된 적용대상·기준시점을 뜻한다. 임의 사례를 만들지 않는다.
- 일정이 지나치게 복잡하면 별첨 참조를 제안하되 승인 없이 생략하지 않는다.

### 7. 내부 QA 후 승인받는다

- `references/quality-checklist.md`를 적용한다.
- 미해결 충돌·누락·근거 불명 항목이 있으면 최종 확정을 요청하지 않는다.
- 문제가 없으면 반드시 `최종본으로 확정할까요?`라고 묻는다.
- `최종 확정`, `승인`, `이대로 저장` 같은 **명시적인 답만** 최종 승인으로 본다.

### 8. 승인 후 저장한다

- **승인 전에는 결과 파일을 만들지 않는다.**
- 승인 후 저장 위치를 물은 뒤 Markdown으로 저장한다. 통상 원문이 있는 폴더가 기본값이다.
- 같은 파일명이 있으면 덮어쓰기 전에 확인한다.
- 요청 시 동일 내용의 단순 흑백 HTML을 추가한다. HWP 붙여넣기 가독성을 우선하고 A4 인쇄비율에 과도하게 맞추지 않는다.

파일명 원칙

- 단일 법령: `「법률명」 개정안 주요내용.md`
- 공통 정책 아래 여러 법령: `「공통 정책명」 후속 법령 개정안 주요내용.md`
- 공통 정책명이 없는 여러 법령: `「주제명」 관련 법령 개정안 주요내용.md`

저장 후에는 다음이 필요한지만 묻고 자동 작성하지 않는다: 임원보고용 요약 / 협회 영향·추진계획 / 검토의견.

## 핵심 작성 원칙 (요약)

상세는 `references/writing-manual.md`.

- **역할 분리**: 제목은 `대상·세목·개정방향`, 본문은 `적용요건·효과·기한`, 주석은 `흐름을 끊는 예외`만. **제목이 말한 것을 본문에서 반복하지 않는다.**
- **조문 표기**: `§`가 이미 "제○조"이므로 `§92의2`로 쓴다. `§92조의2`는 틀린 표기다.
- **개정유형**: 처분문구 기준. 섞이면 `§104⑦ 개정·⑧ 신설`처럼 조문별로 구분한다.
- **표**: 독자가 자기 값을 찾아 대조해야 할 때만 쓴다. 단순 열거형 예외는 축이 둘이어도 각주 한 줄로 처리한다.
- **법령 순서**(기본값): 개인 세제 → 보유세 → 법인 세제. 회원사 관심도에 따라 조정 가능.

## 금지사항

- 제공 원문을 무시하고 웹 검색만으로 개정내용을 확정하지 않는다.
- **이번 산출물의 대상 법령 밖 자료(샘플·참고용 상위법 등)의 내용을 본문에 넣지 않는다.**
- 조문에 없는 정책효과나 협회 입장을 추론해 넣지 않는다.
- 신설·삭제를 숨기거나 조문번호를 생략하지 않는다.
- 시행일·적용례를 개정취지나 보도자료만 보고 추정하지 않는다.
- 1차 초안을 샘플과 똑같이 만들려고 관련 조문을 선제적으로 버리지 않는다.
- 샘플의 알려진 오류(`references/sample-notes.md`)를 형식 벤치마크라는 이유로 재현하지 않는다.
- 사용자 승인 전 파일 저장, 기존 파일 덮어쓰기, 후속 산출물 작성을 하지 않는다.
